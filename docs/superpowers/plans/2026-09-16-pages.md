# TradingView dashboard implementation plan

Approved approach: official TradingView widgets on GitHub Pages; Pine drawings remain in the user's TradingView layout. No reconstructed charts or screenshot claims.

1. Add `pivot_watch/site.py`: `build(out, destination, config, now)` renders escaped HTML from fresh analysis, copies only eligible Pine files, and substitutes explicit unavailable reports if input is missing, invalid or older than six hours. No account credentials or raw provider responses are published.
2. Add `web/style.css` and `web/dashboard.js`: accessible market selection, responsive genuine TradingView 4H widgets, source timestamps, six-hour expiry banner, conditional levels and clearly separated quote/confirmed close. Every widget uses its exact exchange symbol.
3. Extend the existing Actions workflow to build/upload Pages after analysis (including partial failures), then deploy with a separate least-privilege `github-pages` job. Preserve state handling and report failures.
4. Test missing/stale data, escaping, download eligibility and successful generation for all three markets. Run the existing signal tests. Check generated HTML and JavaScript syntax.
5. Document Pages setup, public output, and one-time Pine installation. Package the source and save the updated ZIP. Remote deployment still requires an identified repository and Pages setup.

# Screener implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline; one final independent review.

**Goal:** A runnable stock/crypto swing screener with regime, alerts, and paper journal.
**Architecture:** Separate screener package reusing pivot_watch transports and atomic writes; pure engine, market data, runner/storage, HTML renderer.
**Tech Stack:** Python 3.12 standard library, SQLite, Alpaca, Binance.
**Spec:** docs/superpowers/specs/2026-09-29-screener-design.md

## Global constraints
- No orders, no development Telegram sends, no changes to baseline signals.
- Only completed verified candles; no hindsight fills; unknown costs block entry.
- Credentials in environment; errors never include credential-bearing payloads.

## Review focus
- Overnight/holiday gaps are expected for stocks but missing session bars are errors.
- Stale quotes or delayed processing cannot become fresh paper entries.
- Repeated runs preserve setups and never duplicate paper fills.
- Provider revisions cannot silently move frozen levels.
- Malformed provider fields and configuration fail closed with useful status.
